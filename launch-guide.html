MKDRS website · setup reference

Getting the new site live

A step-by-step guide for whoever on the volunteer team is doing the technical setup. No coding needed — you're mostly clicking "connect" between a few free accounts. Budget around 30–45 minutes for steps 2–6, done once. Step 1 is an optional local test. Steps 7 onward are what everyday editors will use.

What you're setting up: the site's code lives in a free GitHub repository. Netlify builds it into a live website and hosts it for free. Decap CMS gives editors a simple form-based screen at mkdrs.org.uk/admin — no code, no GitHub login needed for them.
1

Test the editor on your own computer first (optional but recommended)

Before putting anything online, you can try the admin editor locally, with no GitHub or Netlify account. This proves the editor screen actually saves your changes to the page files.

  1. Unzip the site files. In a terminal, inside that folder, run npm install once.
  2. Open two terminal windows in that folder. In the first, run npx decap-server and leave it running — this is the small local helper that saves edits to disk.
  3. In the second, run npx eleventy --serve and leave it running — this builds and serves the site.
  4. Open http://localhost:8080/admin/ in your browser. Skip the login screen (there isn't one locally) and edit a page. Click Publish.
  5. Refresh http://localhost:8080/ and check your change appears on the live page.

This step only works with an internet connection, because the editor screen loads its interface from a public code library. Once you're happy it works, move on to putting the site online for real.

2

Put the code on GitHub

GitHub is where the site's files live and where Netlify will pull them from.

  1. Create a free account at github.com if the team doesn't have one already.
  2. Create a new, empty repository — call it mkdrs-website. Keep it private or public, either works.
  3. Unzip the site files I sent you. In a terminal, inside that unzipped folder, run:
git init
git add .
git commit -m "Initial site"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/mkdrs-website.git
git push -u origin main

If nobody on the team is comfortable with the terminal, GitHub Desktop (a free app) does the same thing by clicking buttons instead.

3

Connect Netlify to that repository

  1. Create a free account at netlify.com — sign up with the same GitHub account for the smoothest setup.
  2. Choose Add a new site → Import an existing project → GitHub, then pick the mkdrs-website repository.
  3. Netlify will detect the build settings automatically from the site's netlify.toml file (build command npm run build, publish folder _site). Just click Deploy.

After a minute or two you'll get a live web address like random-name-123.netlify.app. That's the real site — check it over before moving on.

4

Turn on editor logins

This is what lets your volunteer editors log in to /admin without touching GitHub.

  1. In the Netlify site dashboard: Site configuration → Identity → Enable Identity.
  2. Under Identity settings, set registration to Invite only (so strangers can't sign themselves up).
  3. Still under Identity, enable Git Gateway — this is what lets Decap CMS save changes back to GitHub on the editor's behalf.
  4. Go to the Identity tab and click Invite users for each volunteer who'll edit the site. They'll get an email to set a password.
5

Point mkdrs.org.uk at the new site

Since you already own the domain:

  1. In Netlify: Domain management → Add a domain, enter mkdrs.org.uk.
  2. Netlify will show you either a nameserver change or a couple of DNS records (A/CNAME) to add at wherever the domain is currently registered.
  3. Netlify also issues a free HTTPS certificate automatically once the DNS change is live — usually within an hour.
Keep WordPress live until this step is confirmed working. Don't cancel the old hosting until the new site is loading correctly at the real domain.
6

Turn on the contact form

The contact form is already wired up for Netlify's built-in form handling — nothing to install. Once the site is deployed:

  1. Go to Forms in the Netlify dashboard and confirm the contact form was detected.
  2. Under Forms → Settings → Form notifications, add an email notification to whichever address the volunteer team checks (e.g. info@mkdrs.org.uk).
About "routing to the right person": the form has a topic dropdown (membership, Cheder, hall hire, and so on), but a free Netlify site sends every submission to one inbox, not different people per topic. The topic still shows up clearly at the top of each email, so whoever monitors that inbox can forward it on. True auto-routing to named owners is possible later using a paid Netlify tier or a simple Zapier automation — worth revisiting once the site is live and you know submission volume.
7

How editors update content day to day

  1. Go to mkdrs.org.uk/admin and log in with the email that was invited in step 3.
  2. Every page appears on the left under Website pages — e.g. "About us: Our history", "Contact us".
  3. Click a page, edit the text in the form fields, then click Publish top-right.
  4. The live site updates automatically within a minute or two — no code, no waiting on anyone.

Editors never see GitHub, git, or any code. If someone edits something and wants to undo it, the site's history is kept in GitHub and I can help roll it back.

8

Before you tell people the site is live

Four pages were built as clearly-marked placeholders because the source document flagged them as not yet written. Fill these in via /admin before launch:

PageWhat's needed
SafeguardingThe actual policy and safeguarding lead's contact details
Privacy noticeWhat data is collected (contact form, membership) and how it's used
Cookie noticeConfirm no tracking cookies are in use, or list any that are added later
Accessibility statementKnown limitations and a contact for accessibility feedback

Also from the source document's own checklist

  • Add the synagogue's telephone number (Contact us page)
  • Add hall capacity, facilities and accessibility details (Hall hire page)
  • Add the registered charity number (site footer)
  • Confirm current interfaith partner organisation names
  • Confirm consent for any photographs added later; no photographs of children
Built with Eleventy (static site generator) + Decap CMS (free, git-based editor) + Netlify (free hosting). No recurring cost at this scale.
